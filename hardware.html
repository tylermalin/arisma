EnclaveEdge X1.

A security gateway that gives every machine behind it a hardware identity, with no changes to the machines themselves.

platform / hardware

Insecure on one side. Zero trust on the other.

The X1 sits between a site's machines and the network. It takes in their unauthenticated local traffic, signs it inside a discrete TPM 2.0 enclave, and sends it on over mutual TLS. The private key never leaves the chip.

Enclave
Discrete TPM 2.0 on its own SPI bus
Operating range
−40 to 105 °C with the NXP option
Field buses
2× CAN FD, RS-485, USB 2.0
Uplink
Ethernet with LTE Cat-M1 failover
Updates
Signed A/B images with automatic rollback

Seven industries, one enclave interface.

Each vertical runs as its own container with its own ingest driver. All of them hand their data to the same TPM interface, so one gateway design covers every site.

It refuses to start if anything changed.

The boot ROM checks the bootloader. The bootloader hashes the kernel and its extensions into the TPM's PCR registers. If a measurement does not match, the gateway halts before any container runs, so it never signs data on a modified system.

Trusted from the factory to the last update.

The gateway's identity is created inside the chip at manufacture and proven again every time it connects or updates.

  1. 01

    Identity made at the factory

    A unique endorsement key pair is generated inside the TPM during production. The factory certificate authority signs the public half, which becomes the gateway's permanent birth certificate.

  2. 02

    Zero touch provisioning

    Plugged into a WAN, the gateway calls out to the orchestration layer and presents a TPM signed attestation quote proving its firmware is intact. No one configures it by hand.

  3. 03

    Signed updates with rollback

    The root filesystem is atomic and read only. Updates arrive as signed images on an A/B pair. If a new image fails measured boot, the gateway falls back to the last good one.

Every message carries its own proof.

The gateway packages the raw readings, the state of the hardware, and a signature made inside the TPM into one envelope. Change any reading and the digest no longer matches the signature.

Specifications.

Two compute options share one enclave design, board layout, and software image.

Compute
NXP i.MX8M Nano QuadLite, industrial range −40 to 105 °C, or Raspberry Pi Compute Module 4, industrial variant
Hardware enclave
Infineon OPTIGA™ TPM SLB 9670, discrete, on a dedicated SPI bus
Enclave certification
The SLB 9670 is certified to Common Criteria EAL4+ and FIPS 140-2 Level 2
Memory
2 GB LPDDR4
Storage
16 GB eMMC 5.1 in SLC mode, for write endurance and resistance to corruption
Local OT network
1× RJ45 Gigabit Ethernet, isolated, with routing and forwarding disabled
WAN
1× RJ45 10/100 Ethernet, or a Nano SIM slot for LTE Cat-M1 failover
Expansion
2× isolated CAN FD, 1× RS-485 (Modbus), 1× USB 2.0 host
Operating system
Hardened, read only root filesystem on Yocto Project Linux or Ubuntu Core
Boot
Hardware enforced measured boot into TPM PCRs; halts on any mismatch
Containers
LXC or Docker with namespace, cgroup, and seccomp isolation
SPI interconnect referencePin mapping between the host and the TPM, for hardware engineers

Standard four wire SPI, plus an interrupt for asynchronous alerts, a reset line so the host can power cycle the enclave, and a presence trace that halts the system if the board is tampered with.

Device tree overlay, Raspberry Pi CM4

Binds the SLB 9670 to SPI0 chip select 0 through the kernel's TPM TIS SPI driver, with reset on GPIO 25 and the interrupt on GPIO 24. Saved as tpm-slb9670-overlay.dts.

dtc -@ -I dts -O dtb -o tpm-slb9670.dtbo tpm-slb9670-overlay.dts
/dts-v1/;
/plugin/;

/ {
    fragment@0 {
        target = <&spi0>;
        __overlay__ {
            #address-cells = <1>;
            #size-cells = <0>;
            status = "okay";

            spidev@0 { status = "disabled"; };

            tpm_enclave: slb9670@0 {
                compatible = "infineon,slb9670", "tcg,tpm_tis-spi";
                reg = <0>;
                spi-max-frequency = <32000000>;
                status = "okay";
                gpios = <&gpio 25 1>;
                interrupt-parent = <&gpio>;
                interrupts = <24 1>;
            };
        };
    };
};
